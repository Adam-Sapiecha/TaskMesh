# Rust engine migration — 2026-10-21

The API, worker, controller, migrations, public session admission and static-file
server now run in Rust. React/TypeScript remains the browser interface. The Go
implementation is retained in Git at `go-engine-v0.1`, not in the current runtime.

## Implementation

- Rust 1.99.1, Tokio asynchronous runtime, Axum HTTP, SQLx PostgreSQL.
- `src/storage.rs`: transactional submission, capacity, worker identity, lease
  fencing, renewal, acknowledgements, recovery, sessions and retention.
- `src/sql.rs`: the original coordination SQL retained with the same lock order
  and conditional updates. Queue then worker locking enforces concurrency caps;
  public admission locks budget then session then queue.
- `src/worker.rs`: bounded Tokio tasks, heartbeat, renewals, 30-second drain,
  task deadlines, dropped futures on cancellation and caught handler panics.
  SHA-256 yields every 128 rounds. This is cooperative cancellation, not an
  arbitrary-code sandbox or forced interruption of blocking native code.
- `src/api.rs`: owner bearer authentication or isolated visitor sessions,
  request bounds, exact Origin checks, global rate/concurrency limits, CSP,
  safe static asset serving and the existing HTTP contract.
- `Dockerfile`: Node frontend build, pinned Rust Bookworm builder, non-root
  Debian Bookworm slim runtime. Both Compose stacks use the same ARM64 image.
- `Cargo.lock`, pinned toolchain, Rust formatting/Clippy/tests in CI. Integration
  tests require an explicit disposable database and isolate themselves by schema.

## Compatibility

Migration files 001 and 002 are byte-for-byte unchanged. Their stored SHA-256
checksums were verified against both running databases before deployment. The
private database previously had only 001; its migration added the existing 002
public-session tables/optional column without changing existing jobs. Public
migrations were already current. No volume was replaced or reset.

HTTP paths, job fields, worker modes, environment configuration, cookie name/path
and SHA-256 session hashes are retained. Health responses additionally report
`"runtime":"rust"`. Idempotency normalization preserves the Go representation,
including integral numbers, HTML/Unicode escaping and RFC3339Nano timestamps.
Golden hashes were generated by the actual previous Go executable and checked
in Rust tests. A live pre-migration idempotency key was also reused successfully
after migration with HTTP 200 and the same job ID.

## Verification performed

Native Linux ARM64 on the Raspberry Pi, using an isolated PostgreSQL 17 container:

- `cargo fmt` and `cargo clippy --locked --all-targets -- -D warnings` passed.
- `cargo test --locked`: **4 unit tests + 8 integration/process tests passed**.
- 1000 reports submitted over HTTP by 10 producers, executed by three separate
  Rust worker OS processes. All 1000 succeeded with 1000 successful attempts;
  API replacement preserved results. This is an acceptance scenario, not a
  production throughput or resource-capacity guarantee.
- Competing claims, queue/worker caps, priority and delayed scheduling, migration
  checksum tampering, stale ACK/renewal rejection, lease expiry/recovery, retry
  exhaustion, permanent failures, cancellation and graceful worker shutdown.
- Transactional public quotas under concurrent submission, idempotency reuse at
  quota, separate session scopes, global budget rollback, retention preserving
  private and unfinished jobs. HTTP tests cover cookie flags, Origin rejection,
  cross-session job/event/attempt/cancel denial, body/computation limits and
  non-exposure of the owner API.
- Frontend TypeScript and production builds passed locally and in the ARM64 image.

Live checks after deploying the final image:

- Both stacks' API/console, three workers and controller passed readiness and
  Docker health checks; health reports `runtime=rust`, schema 002.
- A session and completed report created by Go remained readable by Rust. Its
  idempotent resubmission returned the same job, without charging another job.
- Numeric report, Unicode text analysis and 1000-round SHA-256 all succeeded over
  public HTTPS. The independent HTTP client verified secure cookie flags,
  cross-session 404, private API 404 and invalid-Origin 403.
- The existing browser session retained its five earlier reports. A sixth text
  job executed in Rust and displayed 29 Unicode characters, 6 words, 2 lines,
  one attempt and the PENDING → RUNNING → SUCCEEDED history.
- Owner API authentication, idempotency, report result, attempt and event reads
  passed. All 132 pre-existing private jobs remained; one new verification job
  brought the private count to 133. Public count was 12 after verification.
- Backups of both live databases were created before replacement and successfully
  restored into separate temporary databases (132 private / 8 public jobs at the
  backup snapshot). Those temporary restore databases were then removed.

The Rust process tests are not Go race-detector tests. Earlier reports describe
the Go version and are explicitly labelled historical. No full-host reboot,
hostile-traffic capacity test or high-availability claim is made.

enforced here. Rust has no Go `GOMEMLIMIT`; the obsolete Go variables were removed.
CPU/PID limits, bounded handlers, admission quotas and separate stacks remain.
